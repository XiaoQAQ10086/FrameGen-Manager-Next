# 资产更新与旧部署清除

目标：软件升级后，如果内置资产 pack 版本变化，先检测受影响的游戏，由用户确认后清除旧部署，再由用户手动重新部署。不会自动重装，也不会在启动时静默删游戏文件。

## 触发条件

- 只比较部署 manifest 中记录的 `PackId` / `PackVersion` 与当前可解析 pack 的版本。
- 两者相同 → 不处理。
- manifest 不存在、已 `Restored` 或 `RolledBack` → 不处理。
- pack 缺失、版本不同 → 该游戏进入对应功能分组。
- 用户修改文件导致的 `Conflict` 但不涉及 pack 版本变化 → 不触发批量清除，仍按单游戏冲突处理。

检测只读，不写游戏目录。

## 功能分组

| 功能 | 部署目录 | 清除方式 |
|---|---|---|
| 帧生成 | 游戏目标目录 | 部署引擎还原原文件 |
| Smooth Motion | 游戏目标目录 | 还原文件并关闭驱动级 SM 设置 |
| DLSS5 | 游戏目标目录 | 完整卸载：ReShade 卸载器、模块、INI、日志、插件、模型和残留 |

只有某个功能确实存在版本变化的部署时，才显示该功能；例如只有 SM 更新，弹窗只显示 SM。

## 用户流程

1. 启动后后台检测，完成后弹窗：
   - 动态列出受影响功能与游戏数量。
   - 提示先退出所有游戏、暂时关闭杀毒软件。
   - 明确说明：清除后需要手动重新部署。
2. 用户选择“稍后”：
   - 不写文件。
   - 页面顶部保留待处理提示，点击可重新打开弹窗。
3. 用户选择“一键清除”：
   - 清除前重新读取 manifest；如果用户在等待期间已经手动更新了某个游戏，它不会被清除。
   - 串行逐游戏执行，显示进度，可取消。
   - 每个游戏成功/失败独立记录，不因为一个失败中断整批。
4. 结果弹窗：
   - 成功：提示已清除数量，请手动重新部署。
   - 失败：显示【清除/还原失败的游戏：】，列出游戏名、错误码、失败原因、路径，并提供打开目录；提示手动清理。

## 成功与失败判定

- 帧生成 / SM：还原报告必须 `Conflicts=0`、无 leftovers、无 warnings，且驱动设置写回成功。
- DLSS5：卸载报告 `IsClean=true`，即 `Remaining` 为空。
- 成功：清除后丢弃该部署的 manifest 和备份目录。
- 失败：保留 manifest 和备份，列出原因；用户关闭游戏/杀毒软件后可重试，或手动清理。
- 用户修改过的文件不会被强删；会作为失败列出。

## 与其他流程的关系

- 全局资产更新存在时，单游戏卡片应显示“待清理”，不要同时出现“更新/清除”两套语义。
- 清除完成后，游戏回到未部署状态，由用户手动点“部署”。
- 不自动结束游戏进程；检测到占用时直接失败并报告。
- DLSS5 只处理本工具记录过部署的游戏；用户自己安装的 ReShade 不在自动卸载范围内。

## 命令

```powershell
fgm-next assets check [--json]
fgm-next assets clear --yes
```

`check` 只读；`clear` 必须显式 `--yes`。

## 测试

- `Core.Tests/AssetMaintenanceServiceTests`：只报告变化的 family、相同版本不报告、干净还原、冲突/残留失败、DLSS5 残留失败。
- `Infrastructure.Tests/DeploymentEngineTests`：有冲突的还原保留 `Partial` manifest，便于重试。
