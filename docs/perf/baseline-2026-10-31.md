# 性能基线（2026-10-31）

## 环境

- Windows 11 x64，Ryzen 5 9600X（12 逻辑核心），RTX 3070，驱动 621.01
- Release 便携版，共享 `D:\fgm-perf-wt\data`：7 个游戏，封面缓存预热，`showCovers=true`
- 宿主内存取 `Get-Process` Working Set；WebView2 通过 `Win32_Process.CommandLine` 过滤
  `msedgewebview2.exe` 中带本程序 profile（`9fef62be2247`）的进程
- 每种场景单独启动，等待 12–60 秒后再采样

## 启动（从 App 构造函数开始计时）

| 里程碑 | 耗时 |
|---|---|
| hostBuilt | 40 ms |
| hostStarted | 146 ms |
| windowLoaded | 372 ms |
| webviewReady | 623 ms |
| uiReady（首屏可交互） | **717 ms** |

进程创建到 App 构造之间约 80–120 ms，冷启动整机约 0.8 s。

## 内存

| 指标 | 数值 |
|---|---|
| 宿主 Working Set | 174–177 MB |
| 宿主 Private Bytes | 98 MB |

| 空闲增长 | 50 秒内无增长（修复前 30→60 秒 +100 MB） |

### 回归定位

| 版本 | 说明 | 宿主 Working Set |
|---|---|---|
| `8fbfeb6` | 内存改动之前 | 149–152 MB |
| `6b4f006` | 加入 JS 堆上限、GC Conserve、Low、工作集修剪 | 263 MB |
| `6a856d8` | 移除 Low、页面切换已还原 | 268–270 MB |
| 去掉逐游戏 NVAPI 查询 | 仅定位 | 148.5 MB |
| **批量 NVAPI（当前）** | 库页/SM 页一次会话 | **166–177 MB** |

根因：每个游戏单独 `NvApiSession.Open()` 会执行 `DRS_LoadSettings`，驱动重复加载整份
profile 数据库，约 100 MB 原生内存且不被托管 GC 回收。封面和
`MemoryUsageTargetLevel` 都不是主因。

|---|---|

| 库扫描（缓存热） | 264 ms |
| 帧生成部署（约 213 MB） | 811 ms |
| 帧生成还原 | 372 ms |
| DLSS5 离线安装（523 MB，此前实测） | ~1.5 s |

## 本轮已实现

- `INvApiSmoothMotion.GetStatesAsync`：单 NVAPI 会话批量读取；库页和 SM 页共用。
- `PackRepository` 进程内缓存：同一 pack 不再逐游戏重复读取和校验 `pack.json`。
- 启动里程碑日志：`startup.hostBuilt` / `hostStarted` / `windowLoaded` /
  `webviewReady` / `uiReady`，便于后续回归比较。

## 暂不执行的项（没有数据支撑）

- 封面延迟加载/更小缩略图：封面开启时内存已回到 177 MB，继续压缩收益不明确。
- 扫描进一步并行：缓存热时 264 ms，冷启动主要耗时在首次文件系统遍历，已用满核心。
- 部署并行写：811 ms 已是 IO 主导，收益低于回滚复杂度风险。
- 虚拟滚动：当前 7 个游戏，DOM 开销可忽略；等真实库 ≥50 个游戏再测。

## 复现

```powershell
$env:FGM_DATA_DIR = 'D:\fgm-perf-wt\data'
$p = Start-Process -FilePath '<portable exe>' -PassThru
Start-Sleep -Seconds 12
Get-Content '<data>\logs\app-*.log' | Select-String 'startup\.'
(Get-Process 'FrameGenManager-Next').WorkingSet64 / 1MB
Get-CimInstance Win32_Process -Filter "Name='msedgewebview2.exe'" |
    Where-Object { $_.CommandLine -like '*9fef62be2247*' }
```
