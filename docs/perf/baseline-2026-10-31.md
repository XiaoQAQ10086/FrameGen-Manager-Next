# 性能基线（2026-10-31）

## 环境

- Windows 11 x64，Ryzen 5 9600X（12 逻辑核心），RTX 3070，驱动 621.01
- Release 便携版，共享 `D:\fgm-perf-wt\data`：7 个游戏，封面缓存预热，`showCovers=true`
- 宿主内存取 `Get-Process` Working Set；WebView2 通过 `Win32_Process.CommandLine` 过滤
  `msedgewebview2.exe` 中带本程序 profile（`9fef62be2247`）的进程
- 每种场景单独启动，等待 12–60 秒后再采样

### 回归定位

| 版本 | 说明 | 宿主 Working Set |
|---|---|---|
| `8fbfeb6` | 内存改动之前 | 149–152 MB |
| `6b4f006` | 加入 JS 堆上限、GC Conserve、Low、工作集修剪 | 263 MB |
| `6a856d8` | 移除 Low、页面切换已还原 | 268–270 MB |
| 去掉逐游戏 NVAPI 查询 | 仅定位 | 148.5 MB |
| **批量 NVAPI（当前）** | 库页/SM 页一次会话 | **166–177 MB** |

根因：每个游戏单独 `NvApiSession.Open()` 会执行 `DRS_LoadSettings`，驱动重复加载整份
profile 数据库，约 100 MB 原生内存且不被托管 GC 回收。封面和
`MemoryUsageTargetLevel` 都不是主因。

## 大游戏库压力测试（306 个游戏）

| 场景 | 结果 |
|---|---|
| 修复前 `games.state` | 4294–6500 ms（封面网络请求阻塞） |
| 修复后 `games.state` | **273 ms** |
| 修复后宿主 Working Set | 178 MB（仅库页）；浏览 SM/DLSS5 后约 208 MB |
| 修复后 `sm.state`（306 游戏） | 128 ms |
| 修复后 `dlss5.state`（306 游戏） | 9 ms |
| 首屏 DOM | 只渲染前 40 张卡片，滚动到底再追加 |

措施：

- 目标目录没有任何 pack 文件、manifest 或旧版记录时，帧生成检查直接返回 `NotDeployed`，不再为每个游戏读取 INI 模板和构建完整计划；
- 游戏数 >40 时不再在状态构建阶段联网下载封面，只使用本地/缓存封面或 EXE 图标兜底；
- 前端卡片分批渲染（40/批），接近底部时追加；
- `games.state count/elapsed` 结构化日志保留，便于继续观察。

SM 页与 DLSS5 页也使用同一策略：>40 个游戏时不再联网下载封面；DLSS5 对空目录直接返回 `NotDeployed`，不再为每个游戏构建 114 文件计划。306 游戏实测 SM 128 ms、DLSS5 9 ms，均在可接受范围。

## 扫描内存泄漏（2026-10-31 修复）

用户反馈每点击一次“扫描游戏”内存只涨不降。用连续扫描复现，按宿主与 WebView2 分开计时：

| 连续扫描 | 宿主 Working Set | 宿主 Private | WebView2 Working Set |
|---|---:|---:|---:|
| 基线 | 173.0 MB | 93.3 MB | 346.9 MB |
| 1 | 206.4 MB | 120.6 MB | 381.8 MB |
| 2 | 226.2 MB | 140.2 MB | 384.2 MB |
| 3 | 243.2 MB | 156.6 MB | 386.4 MB |
| 6 | 301.4 MB | 215.1 MB | 377.9 MB |

宿主每次约 +20 MB，WebView2 基本平稳，排除前端 DOM/封面缓存。根因是
`NvApiSession.Open()` 每次调用 `NvAPI_Initialize` 并打开 DRS 会话。
`NvApiNative.IdDestroySession` 原先写成 `0xDAEFF8B0`，这台驱动的
`nvapi_QueryInterface` 返回空指针；destroy 又被当作可选接口，所以会话从未
释放，`NativeLibrary.Free` 也无法回收驱动侧会话数据。同时 `Dispose` 未调用
`NvAPI_Unload`，初始化引用也不递减。

修复：将 `DRS_DestroySession` 改为 `0xDAD9CFF8`，绑定 `NvAPI_Unload`
（`0xD22BDD7E`），在 `Dispose` 与失败清理路径中依次销毁会话、递减初始化
引用、释放库句柄。用 Create/Load/Destroy/Unload 探针连续 4 次验证，工作集
稳定在 76 MB。修复后同样连续扫描 8 次：

| 连续扫描 | 宿主 Working Set | 宿主 Private | WebView2 Working Set |
|---|---:|---:|---:|
| 基线 | 158.4 MB | 77.8 MB | 348.2 MB |
| 1 | 171.7 MB | 88.5 MB | 374.9 MB |
| 4 | 173.8 MB | 88.4 MB | 389.4 MB |
| 8 | 178.0 MB | 92.3 MB | 399.7 MB |

宿主 8 次扫描只从 158.4 MB 升到 178.0 MB，且 Private Bytes 基本持平
（77.8 → 92.3 MB），不再按次线性增长；WebView2 前几次扫描有图片/脚本缓存
预热，之后趋于平稳。NVAPI 为硬件依赖路径，CI 无法覆盖，回归验证通过 CLI/UI
连续扫描并记录进程内存。

## 本轮已实现

- `INvApiSmoothMotion.GetStatesAsync`：单 NVAPI 会话批量读取；库页和 SM 页共用。
- `PackRepository` 进程内缓存：同一 pack 不再逐游戏重复读取和校验 `pack.json`。
- 启动里程碑日志：`startup.hostBuilt` / `hostStarted` / `windowLoaded` /
  `webviewReady` / `uiReady`，便于后续回归比较。

## 暂不执行的项（没有数据支撑）

- 封面延迟加载/更小缩略图：封面开启时内存已回到 177 MB，继续压缩收益不明确。
- 扫描进一步并行：缓存热时 264 ms，冷启动主要耗时在首次文件系统遍历，已用满核心。
- 部署并行写：811 ms 已是 IO 主导，收益低于回滚复杂度风险。
- 虚拟滚动：当前 7 个游戏，DOM 开销可忽略；等真实库 ≥50 个游戏再测。

## 自动化 smoke

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ./build/perf-smoke.ps1
```

默认阈值：启动 ≤2500 ms、宿主 ≤220 MB、WebView2 子进程 ≤450 MB。当前实测
718 ms / 170.5 MB / 349.7 MB。脚本先只作为本地与 nightly 参考，稳定后再考虑加入 CI 失败门禁。
