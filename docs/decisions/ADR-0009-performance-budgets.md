# ADR-0009：性能预算与测量规则

- 状态：Accepted
- 日期：2026-10-31

## 背景

低内存和快速启动是产品目标之一，但之前的“优化”缺少基线，出现过把 `MemoryUsageTargetLevel.Low` 当优化、实际让宿主多占约 95 MB 的情况；也出现过逐游戏打开 NVAPI DRS 会话，导致整库状态加载多占约 100 MB。

## 决定

1. 任何性能改动必须先记录基线、再测量、再提交；没有前后数据的 PR 不合并。
2. 基线固定为：Release 便携版、同一数据目录、封面缓存预热、同一机器和驱动；每个场景至少 3 次，取中位数。
3. 内存同时记录：宿主 Working Set、宿主私有工作集、GC 堆、WebView2 子进程（按父进程链过滤）。
4. 预算（暂定，Phase 1 后复核）：
   - 空闲 5 分钟宿主 ≤ 200 MB（封面开启），≤ 160 MB（封面关闭）
   - 冷启动到首屏 ≤ 2.5 s
   - 扫描 7 个游戏 ≤ 2 s
   - 帧生成部署（约 200 MB）≤ 3 s
5. 禁止项：
   - `MemoryUsageTargetLevel.Low`
   - 每个游戏单独打开 NVAPI/DRS 会话；必须批量复用
   - 对象池、第三方缓存库、Server GC、强制 GC 轮询
   - 并行写游戏目录
6. 性能决策与基线存放在 `docs/perf/`，重大取舍写到 `docs/decisions/`。
7. CI 先跑功能门禁；性能 smoke 脚本只做警告，稳定两周后再考虑设为失败。

## 后果

- 性能改动有可追溯的数据，不再依赖主观感受。
- 逐游戏 NVAPI 会话被禁止，相关页面必须使用批量接口。
